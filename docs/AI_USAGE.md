# Использование ИИ-агентов

Журнал для ответа на вопрос формы сдачи. Пополняется по ходу работы.

## Подход

- Агент — Claude Code. Работает от технического задания (`docs/SPEC.md`): требование → падающий тест → реализация.
- Правила для агента лежат в репозитории: `AGENTS.md` в корне и в каждой части, скиллы в `.agents/skills/`. Агент бэкенда и агент фронта получают разные наборы скиллов.
- Человек принимает решения об архитектуре, утверждает ТЗ и план, проверяет результат на живом Keitaro.

## Журнал

| Этап | Что делал агент | Что решал человек |
|------|-----------------|-------------------|
| Разбор задания | Снял логику редактора с видео-образца (субтитры и кадры), выписал поля Admin API из OpenAPI-схемы Keitaro | Стек фронта, хранилище, GraphQL, BFF на Nitro, деление на две части |
| ТЗ и список фич | Составил `SPEC.md` с нумерованными требованиями и сценариями, `FEATURES.md` с порядком работ | Утверждение плана |
| Папки агентов | Написал проектные скиллы и правила для обеих частей | Состав скиллов и их деление по частям |
| Клиент Keitaro, расчёт долей | Тесты на эталонных ответах трекера, затем клиент; таблица случаев и property-тесты, затем чистая функция долей | Ключ Admin API, запрет записи в трекер до финальной проверки |
| Контракты | Вынес схему GraphQL в `contracts/`, настроил генерацию типов Python и TypeScript и проверку «сгенерированное свежо» | Решение сделать контракты отдельным публикуемым пакетом и единой точкой правки |
| Хранилище | Один контрактный набор тестов, три адаптера: память, SQLAlchemy + Alembic, MongoDB | Требование переключать Postgres ↔ Mongo |
| Создаватор (бэкенд) | Правка контракта → красные тесты R-CR-01…12 → сервис с откатом кампании при сбое → мутация | Правило «домен выбирается или создаётся сразу» |

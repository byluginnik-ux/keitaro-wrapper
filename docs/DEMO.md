# Порядок показа

Для скринкаста и ручной проверки на живом Keitaro. Кампании — только с префиксом `test_bulygin_`; после показа удалить их в трекере.

## Подготовка

```
cp .env.example .env        # KEITARO_API_KEY
docker compose up --build
```

## Создаватор

1. `/create`. Название — продолжение после `test_bulygin_`; страна, оффер (поиск по названию или ID), домен, группа, источник.
2. Отправить пустую форму: у каждого поля своя подпись об ошибке, запрос не уходит.
3. Заполнить и создать. В ответе — имя, ID в Keitaro, ссылки «В редактор» и «Открыть в Keitaro».
4. В Keitaro: у кампании два потока. Первый — фильтр по стране и перенаправление на google.com, второй — оффер с долей 100.

## Редактор

Сценарии из `docs/SPEC.md`, раздел 7.6.

1. **S1.** Открыть кампанию: поток 1 без содержимого, поток 2 с оффером.
2. **S2.** Добавить второй и третий офферы: доли делятся поровну, метка «Не опубликовано», в Keitaro состав прежний.
3. **S3.** «Опубликовать»: в Keitaro те же офферы и доли.
4. **S4.** Добавить оффер и нажать «Отменить»: поток вернулся к опубликованному.
5. **S5.** Удалить оффер: строка «Удалён», 0 %, после публикации его нет в Keitaro. «Вернуть» и опубликовать — он снова там.
6. **S7.** Нажать на долю, ввести 25, Enter: доля закреплена, остальные пересчитаны. Добавить и удалить оффер — закреплённая не меняется.
7. **S8.** Закрепить две доли с суммой больше 100: отказ в панели потока, доли прежние.
8. **S6.** В админке Keitaro убрать оффер из потока, в редакторе нажать «Обновить из Keitaro»: оффер стал «Удалён».
9. При черновике «Обновить из Keitaro» отклоняется с объяснением.

## Остальное

- Переключатель темы: система → светлая → тёмная.
- Всё то же с клавиатуры: Tab, Enter на доле, Esc.
- `STORAGE_BACKEND=mongo docker compose --profile mongo up --build` — тот же сервис на MongoDB.

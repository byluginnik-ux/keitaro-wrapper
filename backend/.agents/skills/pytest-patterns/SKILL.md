# Тесты бэкенда

```
tests/
  fixtures/keitaro/   эталонные ответы Admin API (JSON, без секретов)
  keitaro/            клиент: respx + эталоны
  services/           сервисы: поддельный клиент Keitaro + хранилище в памяти
  storage/            contract.py + запуск для каждого адаптера
  graphql/            schema.execute + снимок schema.graphql
```

## Правила

- Асинхронные тесты — `pytest` с `anyio` (`@pytest.mark.anyio`), один бэкенд `asyncio`.
- Сеть закрыта: настоящий Keitaro недоступен из тестов. Клиент проверяется через `respx`, сервисы — через поддельный клиент (`FakeKeitaro`), реализующий тот же `Protocol`.
- Эталоны сняты с живого трекера и обезличены. Менять их руками нельзя — только переснимать.
- Имя теста — утверждение о поведении; в строке документации номер требования.
- Данные сценариев — из SPEC.md (офферы A, B, C, D; доли 34/33/33).
- Без `sleep`, без зависимости от порядка тестов, без общих изменяемых фикстур.

## Контрактные тесты хранилища

`tests/storage/contract.py` содержит класс с тестами, принимающий фабрику репозиториев. Файлы `test_sqlalchemy.py` и `test_mongo.py` подставляют свою фабрику. Базы поднимаются контейнерами из `compose.yaml` (профиль `test`); без них тесты адаптеров помечаются пропущенными с явной причиной, а в CI пропуск запрещён.

## Доли

Таблица случаев (`pytest.mark.parametrize`) по примерам из SPEC.md плюс property-тесты `hypothesis`: сумма активных равна 100, закреплённые не изменились, у removed — 0, результат детерминирован.

## Команды

```
uv run pytest -x -q                 # всё
uv run pytest tests/services -q     # быстрые
uv run pytest --cov=app --cov-report=term-missing
```

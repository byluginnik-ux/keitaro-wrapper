# Хранилище

## Интерфейсы

`storage/ports.py` описывает `Protocol`-репозитории в терминах доменных моделей: `CampaignRepository`, `StreamRepository`, `AuditLog`, и `UnitOfWork` для атомарных изменений. Методы называются по смыслу (`save_stream_with_offers`), а не по SQL.

Сервисы видят только `ports`. Адаптер выбирается в `main.py` по `settings.storage_backend`.

## Правило двух адаптеров

Любое изменение интерфейса делается в трёх местах одним заходом: `ports.py`, `sqlalchemy/`, `mongo/` — и покрывается контрактным тестом в `tests/storage/contract.py`, который запускается для обоих адаптеров. Поведение, не описанное контрактным тестом, считается неопределённым.

## SQLAlchemy

- Версия 2: `DeclarativeBase`, `Mapped[...]`, `mapped_column`, асинхронный движок (`asyncpg`).
- ORM-объекты не покидают адаптер: наружу — доменные модели.
- Схема меняется только миграцией:
  ```
  uv run alembic revision --autogenerate -m "add stream offers"
  uv run alembic upgrade head
  ```
  Сгенерированную миграцию прочитать и поправить; `downgrade` обязателен. Миграция идёт одним коммитом с изменением моделей.
- Атомарность — транзакция сессии в `UnitOfWork`.

## MongoDB

- `pymongo.AsyncMongoClient`. Поток хранится документом с вложенным массивом привязок офферов: изменение потока — одна запись документа, отсюда атомарность без транзакций.
- Индексы создаются при старте адаптера (`ensure_indexes`), миграций нет.
- Наружу — те же доменные модели.

## Идентификаторы

Наш ID — UUID, создаётся в сервисе, а не базой: одинаково для обоих адаптеров. ID Keitaro — отдельное поле с уникальным индексом.

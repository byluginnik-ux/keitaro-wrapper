# Слои бэкенда

```
app/
  main.py        сборка приложения: настройки, жизненный цикл, подключение /graphql и /health
  settings.py    pydantic-settings, единственное место чтения окружения
  graphql/       типы, запросы, мутации Strawberry
  services/      предметная логика
  keitaro/       клиент Admin API и его модели
  storage/       ports.py + адаптеры
```

## Зависимости — только вниз

```
graphql ──▶ services ──▶ storage.ports
                    └──▶ keitaro
storage.sqlalchemy, storage.mongo ──▶ storage.ports
```

- `services` не импортирует `graphql`, `fastapi`, `strawberry`, `sqlalchemy`, `pymongo`.
- `keitaro` не знает о хранилище, `storage` — о Keitaro.
- Чистые функции (`services/shares.py`) не импортируют ничего, кроме стандартной библиотеки.

## Резолвер

Разобрать вход → вызвать один метод сервиса → отобразить результат или предметную ошибку в тип GraphQL. Условий и циклов по данным в резолвере нет.

## Сервис

- Класс с зависимостями в конструкторе (`KeitaroClient`, репозитории через `Protocol`), собирается в `main.py`.
- Предметные ошибки — исключения из `services/errors.py` с кодом. HTTP-статусы и типы GraphQL сервис не знает.
- Работает с доменными моделями (`dataclass(frozen=True, slots=True)`), а не с ORM-объектами и не с моделями Keitaro.

## Настройки

Читаются один раз в `settings.py`. Модули получают значения параметрами, а не через `os.environ`.

## Лаконичность

- Не заводить слой, абстракцию или параметр «на будущее». Интерфейс появляется, когда есть две реализации (хранилище) или нужна подмена в тестах (клиент Keitaro).
- Нет базовых классов сервисов, универсальных репозиториев и контейнеров зависимостей.

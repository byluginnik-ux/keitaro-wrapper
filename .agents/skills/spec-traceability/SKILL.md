# Прослеживаемость требований

## Правила

- У каждого требования постоянный номер: `R-<раздел>-<nn>` (`R-ED-12`). Номера не переиспользуются; отменённое требование помечается «отменено», а не удаляется.
- Тест ссылается на требование в строке документации или имени: `"""R-SH-04: остаток делится поровну."""`.
- Матрица в разделе 11 SPEC.md называет файл теста для каждой группы требований. Строка заполняется в том же коммите, что и тест.
- Статус фичи в FEATURES.md: `—` → `в работе` → `готово`.

## Изменение требования

1. Правка SPEC.md отдельным коммитом `docs(spec): …` с объяснением причины в теле.
2. Если требование — допущение, обновить и раздел 12.
3. Затем обычный цикл: тест → реализация.

## Проверка покрытия

```
grep -oE 'R-[A-Z]+-[0-9]+' docs/SPEC.md | sort -u > /tmp/spec.txt
grep -rhoE 'R-[A-Z]+-[0-9]+' backend/tests frontend/tests | sort -u > /tmp/tests.txt
comm -23 /tmp/spec.txt /tmp/tests.txt     # требования без теста
```

Перед закрытием фичи вывод по её требованиям должен быть пуст.

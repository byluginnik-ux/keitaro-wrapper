# BFF на Nitro

Цепочка: браузер → `/api/*` (Nitro) → GraphQL бэкенда. Требования R-ARCH-04, R-ARCH-05.

## Делает

- **Собирает экран одним ответом.** Редактор: кампания + потоки + офферы. Форма создаватора: все справочники разом.
- **Проверяет ввод** схемой valibot до обращения к бэкенду: типы, обязательность, формат. Предметные правила (префикс, существование оффера, доли) проверяет бэкенд.
- **Приводит ошибки** к одному виду и статусу:
  ```ts
  interface ApiError { code: string, message: string, field?: string }
  ```
  | Источник | Статус |
  |----------|--------|
  | ввод не прошёл схему | 400 |
  | предметная ошибка из union (`ShareOverflow`, `OfferAlreadyInStream`, `DraftNotPublished`, `EmptyStream`) | 409 или 422 |
  | `KeitaroFailure` | 502 |
  | бэкенд недоступен или `errors[]` | 502, `code: "backend_unavailable"` |
- **Кэширует справочники** на короткий срок (`defineCachedFunction`, десятки секунд). Потоки и офферы потока не кэшируются.
- **Прячет бэкенд:** адрес — в `runtimeConfig.backendGraphqlUrl` (серверная часть), в ответы и в браузер не попадает.

## Не делает

- Не считает доли, не решает, можно ли публиковать, не сравнивает черновик со снимком.
- Не хранит состояние: ни сессий, ни черновиков.
- Не ходит в Keitaro и в базу.
- Не возвращает ответ GraphQL как есть: наружу — плоская модель экрана.

Признак нарушения: в обработчике появилось `if` по предметному полю (`share`, `pinned`, `state`).

## Устройство маршрута

```
server/api/campaigns/[id]/editor.get.ts          экран редактора
server/api/streams/[id]/offers.post.ts           добавить оффер → поток
server/api/streams/[id]/push.post.ts             опубликовать → поток
server/api/creator/options.get.ts                справочники формы
server/api/campaigns.post.ts                     создать кампанию
```

Обработчик: разобрать параметры → проверить схемой → вызвать функцию из `server/utils/` с типизированным документом GraphQL → вернуть модель экрана. Каждое действие редактора возвращает поток целиком.

Типы ответа выводятся Nitro: в компоненте `useFetch('/api/...')` уже типизирован, отдельные интерфейсы для клиента не пишутся.

## Тесты

Логика обработчика живёт в функции из `server/utils/`, принимающей клиент GraphQL параметром. Тест подставляет поддельный клиент и проверяет: что ушло в бэкенд и что вернулось странице, включая каждую ветку ошибок.

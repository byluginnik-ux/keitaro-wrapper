# Состояния редактора

Требования R-UX-10…16. Данные приходят из BFF готовыми; компонент ничего не вычисляет, только показывает.

## Поток

| Состояние | Признак данных | Вид |
|-----------|----------------|-----|
| Опубликован | `dirty: false` | обычная панель |
| Не опубликован | `dirty: true` | полоса `--acc` слева, метка «Не опубликовано», панель публикации внизу |
| Без офферов | `offers: []` | только заголовок и подпись «Поток без офферов»; добавления нет |
| Идёт запрос | локальное | кнопки потока недоступны, у нажатой — индикатор; раскладка не прыгает |
| Ошибка | ответ BFF `{ code, message }` | сообщение в панели потока, черновик на месте |
| Поток изменён в другом окне | ответ BFF `stream_conflict` с полем `stream` | поток заменяется присланным, сообщение в его панели; действие не применено (R-UX-17) |

## Оффер

| Состояние | Признак данных | Вид |
|-----------|----------------|-----|
| Активный | `state: active` | название, доля, значок закрепления, «Удалить» |
| Removed | `removed: true` | текст `--cap`, метка «Удалён», доля `0 %`, «Вернуть» |
| Закреплён | `pinned: true` | закрашенный значок, подпись «Доля закреплена» |
| Доля изменена | `share !== publishedShare` | `33 → 25 %` рядом с долей |
| Новый | `published: false` | метка «Новый» |

Состояние никогда не передаётся одним цветом: у каждого есть текст или значок с подписью.

## Действия

- Каждое действие — запрос к BFF, ответ — поток целиком; компонент заменяет поток ответом. Оптимистичных пересчётов долей на клиенте нет.
- Правка доли на месте: клик или Enter открывает поле, Enter закрепляет, Esc отменяет ввод.
- Добавление — список с поиском по офферам; уже активные в потоке офферы в списке недоступны.
- «Опубликовать» и «Отменить» видны только у потока с `dirty: true`.

## Шкала долей

Сегменты — активные офферы в порядке потока; ширина — доля. Подпись: «Сумма 100 %». У шкалы текстовая альтернатива со списком «оффер — доля».

## Тесты компонентов

На каждую строку таблиц — тест: по данным отрисован нужный текст, метка и доступные действия. Проверять роли и подписи (`getByRole`, `getByText`), а не классы.
